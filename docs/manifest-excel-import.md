# Manifest Excel import

Shipping Line accounts can upload a single-sheet `.xlsx` file for review before
creating a Manifest. The upload does not write records or create containers.

## Format

Row 1 contains the following headers. Column order may change; headers must remain
unique. Every subsequent non-empty row describes one container. Do not merge cells
or use formulas. Hidden rows are still imported. Repeat all Manifest and bill data
on every row.

| Header | Requirement |
| --- | --- |
| Chuyến tàu | Required text, at most 100 characters, identical across file |
| Tên tàu | Required text, at most 250 characters, identical across file |
| Hướng khai | IMPORT / EXPORT, or Nhập khẩu / Xuất khẩu, identical across file |
| Số vận đơn (B/L) | Required text, at most 100 characters; groups rows into bills |
| Người gửi hàng | Required text, at most 500 characters; consistent per bill |
| Người nhận hàng | Required text, at most 500 characters; consistent per bill |
| Số container | Valid ISO 6346 number, registered and not quarantined; unique in file |
| Số niêm chì | Required text, at most 50 characters |
| Trọng lượng (kg) | Numeric Excel cell, greater than 0 and at most 36,000 kg |
| Mô tả hàng hóa | Required text, at most 2,000 characters |

Container ISO/catalog type, ISO size/type and reefer flag come from the shared
equipment registry. Do not add these as editable Excel columns. Manifest number,
creation date and state are generated by the existing save workflow.

Limits: 5 MB compressed, 30 MB expanded, one sheet, 5,000 non-empty data rows,
100 bills and 500 containers per bill. Extra columns, missing/duplicate headers,
merged cells, formula/error cells and contradictory repeated metadata are rejected.
Text cells with formatted weights (for example `18,000 kg`) are rejected; Excel's
numeric display formatting is supported.

## API

Both routes require the same JWT and active Shipping Line account as Manifest CRUD.

- `GET /api/v1/shipping-line/manifests/import/template`: empty `.xlsx` template.
- `POST /api/v1/shipping-line/manifests/import/preview`: multipart field `file`.
  Structural/file errors use 422. Row errors return 200 with `data.valid=false`,
  `totalErrors` and up to 200 `{row,column,message}` entries, with 1-based Excel rows.
  There is no partial Manifest in an invalid response. Valid responses include
  a fresh request key, grouped `manifest`, row/bill counts and total kg.

Used B/L numbers are checked only within the authenticated account. Equipment is
looked up in a batch. Neither lookup writes operational or cargo master fields.
DB connectivity/capacity failures remain service errors, not missing-container errors.

The frontend opens the existing composer after a valid preview. Users can edit,
save a draft or finish. The existing POST save route revalidates the entire payload,
resolves equipment from DB again, and atomically enforces account/bill uniqueness.
Import does not send the Manifest to the port automatically.
Manifest JSON save requests have a scoped 32 MB body limit so a large reviewed
file can be saved; other modules keep their existing default JSON body limit.

## Verification

Run `npm run db:check -- --require-current` in `node-core` first. No migration is
needed. Then run `npm test -- --runInBand src/modules/manifest` and `npm run build`.
The import service/HTTP tests use isolated fake repositories and never seed the
configured database. Existing PostgreSQL persistence tests remain opt-in for the
guarded local test database.
